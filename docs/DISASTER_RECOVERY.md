## 1. RTO/RPO 目标

DoctorAgent 区分两类恢复目标，按数据敏感度与临床依赖度分级。

| 数据类别 | RTO（恢复时间目标） | RPO（恢复点目标） | 说明 |
|----------|---------------------|-------------------|------|
| **Vault（加密病历）** | 1 小时 | 1 小时 | 临床核心数据，最高优先级 |
| **临床服务整体** | 4 小时 | 24 小时 | 含 Index、Audit、Config 全量恢复 |
| **审计日志** | 4 小时 | 0（不允许丢失） | 合规要求零丢失，实时追加 + 同步复制 |
| **配置/密钥材料** | 1 小时 | 0 | 主密钥 Shamir 分片离线保管 |

> RTO/RPO 依据等保三级与 HIPAA 要求设定，需每年由合规官复核。

## 2. 灾难场景分类

| 场景 | 触发示例 | 影响范围 | 首要动作 |
|------|----------|----------|----------|
| **硬件故障** | 磁盘损坏、内存故障、主机宕机 | 单节点服务中断 | 切换备用节点 / 恢复备份 |
| **数据损坏** | SQLite 损坏、FTS5 索引错乱、Vault 文件坏块 | 查询/写入异常 | 从备份恢复 index/vault |
| **密钥丢失** | 主密钥口令遗忘、TPM 损坏、keychain 丢失 | 全部密文不可解密 | **Shamir 分片重组**（§4.3） |
| **勒索软件** | 主机被加密勒索 | Vault/Index/Config 全部受影响 | 离线备份恢复 + 紧急密钥轮换 |
| **数据中心失效** | 火灾、断电、网络分区 | 整站点不可用 | 异地容灾接管 / 降级模式 |
| **人为误操作** | 误删目录、错误轮换密钥 | 部分数据丢失 | 单文件/全量恢复 |
| **内部威胁** | 恶意管理员篡改审计日志 | 合规风险 | HMAC 校验 → 安全应急 → 取证 |

## 3. 备份策略

### 3.1 3-2-1 原则

DoctorAgent 严格遵循 **3-2-1 备份原则**：

- **3** 份数据副本（1 份生产 + 2 份备份）
- **2** 种不同介质（如：本地 SSD + 异地对象存储 / 离线磁带）
- **1** 份离线副本（air-gapped，防勒索软件）

### 3.2 备份对象

| 备份对象 | 路径 | 说明 |
|----------|------|------|
| 加密金库 | `~/DoctorAgent/Vault/` | AES-256-GCM 密文，已加密 |
| 全文索引 | `~/DoctorAgent/Index/` | SQLite + FTS5 |
| 配置 | `~/DoctorAgent/Config/` | `settings.json` 等 |
| 审计日志 | `~/DoctorAgent/Audit/` | NDJSON + HMAC 链 |
| **主密钥材料** | Shamir 分片（3/5 阈值） | 5 名持有人各自保管 1 片，离线介质 |

> **关键约束**：`vault/` + `index/` + `config/` 必须一起备份与恢复，否则索引与密文不一致。主密钥材料**独立离线保管**，不进入常规备份流。

### 3.3 备份频率与保留

| 对象 | 频率 | 保留策略 | 加密 |
|------|------|----------|------|
| Vault + Index | 每 1 小时（增量） | 30 天滚动 + 12 个月归档 | 已加密（Vault 原生 AES） |
| Config | 每次变更 + 每日 | 90 天 | 传输/存储加密 |
| Audit Log | 实时追加 + 每 15 分钟同步 | 7 年（合规要求） | HMAC 链 + 存储加密 |
| Master Key 分片 | 每次轮换 | 永久（直至销毁流程） | Shamir 分片本身 |

### 3.4 触发备份

```bash
# 触发一次远程备份（vault + index + config + audit 原子打包）
doctoragent backup

# 验证备份完整性
doctoragent backup verify --latest
```

### 3.5 备份加密

- 备份包使用独立的**备份密钥**（区别于主密钥）加密
- 备份密钥同样以 Shamir 分片保管
- 离线副本写入一次性写介质（WORM）以防勒索软件加密

## 4. 恢复流程

### 4.1 单文件恢复

适用于误删单份病历、单条索引错乱等小范围事件。

```bash
# 1. 停止 daemon 防止覆盖
doctoragent daemon stop

# 2. 从最近备份中提取目标文件
doctoragent restore file --backup <backup-id> --path "Vault/2026/07/patient_12345.enc"

# 3. 校验 HMAC 与解密一致性
doctoragent vault verify "Vault/2026/07/patient_12345.enc"

# 4. 重建受影响索引
doctoragent index rebuild --path "Vault/2026/07/patient_12345.enc"

# 5. 重启 daemon
doctoragent daemon start
```

- [ ] 已停止 daemon
- [ ] 文件已恢复并校验
- [ ] 索引已重建
- [ ] 审计日志记录恢复事件

### 4.2 全量恢复（新机器）

适用于主机损坏、数据中心失效、勒索软件等需要重建环境的场景。

**前置准备**

- [ ] 新机器满足 `OPERATIONS.md` §2.1 环境要求
- [ ] 已安装 `doctoragent`（同版本，`make check-version` 通过）
- [ ] 已取回最近可信备份包
- [ ] 已召集 ≥3 名 Shamir 持有人（密钥恢复）

**步骤**

```bash
# 1. 初始化空目录结构
doctoragent init --data-dir ~/DoctorAgent

# 2. 解密并恢复 Vault + Index + Config + Audit
doctoragent restore full --backup <backup-id> --target ~/DoctorAgent

# 3. 重组主密钥（见 §4.3）
doctoragent key restore --shamir-threshold 3

# 4. 解锁 vault key 并校验
doctoragent key unlock
doctoragent vault verify --all --sample 100

# 5. 审计日志完整性校验（HMAC 链）
doctoragent audit verify --all

# 6. 启动服务
doctoragent serve &
doctoragent daemon &

# 7. 健康验证
curl -s http://localhost:8000/health
```

- [ ] 目录结构已初始化
- [ ] 全量备份已恢复
- [ ] 主密钥已重组（≥3 分片）
- [ ] Vault 抽样解密成功（≥100 份）
- [ ] 审计 HMAC 链校验通过
- [ ] `/health` 返回 200
- [ ] 控制台可访问
- [ ] 审计日志记录恢复事件并上报合规

### 4.3 密钥恢复（Shamir 分片重组）

主密钥采用 Shamir 秘密共享（3/5 阈值）。**任何单一持有人无法独立恢复**，符合等保三级与最小权限要求。

```bash
# 每位持有人在自己的安全终端执行，输出分片（不传输完整分片）
doctoragent key shamir reveal --holder <holder-id>
# 系统提示输入持有人的口令，输出该分片字符串

# 在恢复终端汇总 ≥3 个分片
doctoragent key restore --shamir-threshold 3 \
  --share "<share-1>" \
  --share "<share-2>" \
  --share "<share-3>"
```

- [ ] 召集 ≥3 名持有人到场（或安全视频会议）
- [ ] 各持有人身份核验（双因素）
- [ ] 分片汇总恢复主密钥
- [ ] 解锁 vault key 成功
- [ ] 旧分片作废，生成新分片并分发
- [ ] 审计日志记录 `key.restore` 事件

> **紧急情况**：若持有人无法到场，启用预先设定的“应急分片托管”（由合规官与法务联合解封的离线信封）。

## 7. 故障切换 (Failover) 降级模式

当 LLM 后端不可用但 Vault/Index/Config 仍正常时，可切换到 **degraded 模式**：引擎降级为确定性规则引擎 + 关键词检索，仍可安全输出（无 LLM 生成内容）。

### 7.1 自动降级

熔断器连续失败达阈值时自动触发：

- `llm_provider` 置为 `None`
- 所有查询走规则引擎 + FTS5 关键词检索
- 控制台标注“LLM 不可用 — 规则引擎模式”
- 审计日志记录 `llm.degraded` 事件

### 7.2 手动强制降级（紧急）

```bash
# 清空 LLM 端点，强制降级
export DOCTORAGENT_MODEL__BASE_URL=""

# 重启服务使降级生效
doctoragent serve --restart
doctoragent daemon --restart
```

### 7.3 降级模式下的能力边界

| 能力 | 正常模式 | 降级模式 |
|------|----------|----------|
| 病历检索 | LLM + RAG 语义检索 | 关键词检索（FTS5） |
| 临床推理 | LLM 生成 | 规则引擎（确定性） |
| 药物相互作用 | LLM 解读 + 知识库 | 知识库规则匹配 |
| 危急值告警 | 支持 | **支持（规则引擎核心能力）** |
| 自然语言总结 | 支持 | **不支持** |

> 危急值告警等安全关键能力在降级模式下**必须保持可用**，由确定性规则引擎保障。

### 7.4 恢复正常模式

```bash
# 1. 确认 LLM 端点恢复
curl -s http://ollama:11434/api/tags

# 2. 恢复端点配置
export DOCTORAGENT_MODEL__BASE_URL="http://ollama:11434/v1"

# 3. 重启并验证
doctoragent serve --restart
curl -s http://localhost:8000/health
```

- [ ] LLM 端点连通性已验证
- [ ] 熔断器已恢复关闭
- [ ] 抽样查询返回 LLM 结果
- [ ] 审计日志记录 `llm.recovered` 事件
- [ ] 通知临床用户恢复正常

### 7.5 降级模式时间上限

降级模式不应长期运行。建议上限：

| 场景 | 最长降级时长 | 超时动作 |
|------|--------------|----------|
| LLM 单点故障 | 4 小时 | 启用备用 LLM 节点 |
| LLM 集群故障 | 24 小时 | 评估是否触发 MAJOR 事件 |
| 异地灾切后 | 72 小时 | 优先恢复主站点 |

超时未恢复须升级为 P1 事件，按 §6 应急联系人流程上报。

## 8. 恢复后验证

灾难恢复完成后，**必须全部通过**以下验证方可宣布恢复完成。验证不通过则视为恢复失败，需重新执行恢复流程。

### 8.1 数据完整性验证

```bash
# Vault 抽样解密
doctoragent vault verify --all --sample 100

# 审计日志 HMAC 链校验
doctoragent audit verify --all

# FTS5 索引一致性
doctoragent index verify
```

- [ ] 100 份抽样病历解密成功
- [ ] GCM 认证标签全部通过
- [ ] 审计 HMAC 链自首条至末条连续无断
- [ ] 索引记录数与 Vault 文件数匹配

### 8.2 服务可用性验证

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/health
# 期望: 200
```

- [ ] `/health` 返回 200
- [ ] 控制台可正常登录
- [ ] daemon 正常消费 Inbox

### 8.3 合规验证

- [ ] 审计日志连续性无缺口（RPO=0 达成）
- [ ] 恢复过程已记录审计事件（`disaster.recovery`）
- [ ] 主密钥分片已重新分发（若执行了密钥恢复）
- [ ] 合规官签字确认恢复完成
- [ ] 恢复报告归档（保留 ≥ 7 年）
