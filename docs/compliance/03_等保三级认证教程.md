# 网络安全等级保护三级认证教程（等保 2.0）

> 本教程面向使用 DoctorAgent 的企业用户，指导您完成网络安全等级保护三级（简称"等保三级"）的定级、备案、整改与测评工作，使 DoctorAgent 部署环境符合医疗信息系统的合规要求。

---

## 适用场景

### 什么是等保 2.0
网络安全等级保护 2.0（简称"等保 2.0"）是依据《网络安全法》建立的、覆盖所有网络运营者的强制性安全保护制度。GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》是核心技术标准。等保分为五级，第三级为"监督检查级"，要求每年开展一次等级测评。

### 为什么医疗信息系统需要等保三级
1. **法律强制要求**：《网络安全法》第二十一条规定网络运营者必须履行等级保护义务。
2. **行业规定**：国家卫健委《医院信息互联互通标准化成熟度测评》《电子病历系统应用水平分级评价》要求核心医疗信息系统达到等保三级。
3. **数据敏感度高**：DoctorAgent 处理患者 PHI（受保护健康信息），属于"重要数据"，按《数据安全法》需较高保护级别。
4. **关键信息基础设施可能**：大型医疗机构的 HIS / EMR 系统可能被认定为关键信息基础设施（CII），需按不低于等保三级保护。
5. **前置合规要求**：NMPA 医疗器械注册、互联网医院资质、医保对接等均可能要求等保三级。

### 必须办理等保三级的场景
- DoctorAgent 部署在医院核心网络，处理**电子病历、检验报告、影像数据**等敏感医疗数据。
- DoctorAgent 作为**互联网医院**或**远程医疗**平台的核心系统。
- 服务对象为**三级医院**或省级及以上医疗机构。
- 处理**超过 100 万条**个人信息（按 GB/T 35273 个人信息安全规范，应定级三级以上）。
- 系统一旦遭到破坏，可能**造成社会秩序损害**或**大量个人隐私泄露**。

### 可考虑等保二级的场景
- 仅部署在诊所、社区卫生服务中心等小型医疗机构。
- 处理数据量较小、敏感度较低。
- 系统破坏影响范围有限。

> ⚠️ **重要提示**：建议 DoctorAgent 部署统一按**等保三级**规划。即使个别客户场景可定二级，按三级建设能覆盖更广合规需求，避免重复投入。

## 办理流程

### 步骤一：定级（确定保护等级）

1. **确定定级对象**：DoctorAgent 部署的整个信息系统（含服务器、网络、应用、数据）作为一个定级对象。
2. **分析受侵害客体**（按 GB/T 22240）：
   - 公民、法人合法权益
   - 社会秩序
   - 公共利益
   - 国家安全
3. **分析侵害程度**（一般 / 严重 / 特别严重）。
4. **确定等级**：
   - DoctorAgent 处理大量患者敏感信息，受破坏将造成**社会秩序损害**或**公共利益损害**，定级为**第三级**。
5. **编制《定级报告》**：包含定级对象描述、受侵害客体分析、侵害程度分析、定级结论。
6. **专家评审**：邀请 3 名以上网络安全专家对定级报告进行评审，出具评审意见。

### 步骤二：备案

1. 准备备案材料（详见"所需材料清单"）。
2. 将纸质材料提交至**所在地设区的市级及以上公安机关网络安全保卫部门**（网安大队）。
3. 公安机关审核材料（约 10 个工作日）。
4. 审核通过后，领取《网络安全等级保护备案证明》（含备案号，如"京公网安备 XXXXXXXXXXXXX 号"）。
5. 备案信息发生变更（系统迁移、定级调整、主体变更）时，需办理**变更备案**。

### 步骤三：差距分析（摸底测评）

1. 选择**等级保护测评机构**（详见"测评机构选择"）。
2. 测评机构对照 GB/T 22239 三级要求，对 DoctorAgent 现状进行摸底测评。
3. 出具《差距分析报告》，列出未达标项（不符合项、部分符合项）。
4. 差距分析覆盖三大维度：
   - **技术要求**：物理、网络、主机、应用、数据
   - **管理要求**：安全管理制度、安全管理机构、安全管理人员、安全建设管理、安全运维管理
   - **新技术要求**（等保 2.0 新增）：云计算、移动互联、物联网、工业控制、大数据

### 步骤四：安全整改方案设计

1. 基于差距分析报告，制定**整改方案**。
2. 整改方案应明确：
   - 整改目标
   - 整改内容（每项不符合的具体措施）
   - 责任人与时间节点
   - 预算估算
3. 整改方案报企业安全负责人审批。

### 步骤五：技术整改实施

按 GB/T 22239 三级要求开展技术整改，覆盖以下六大维度（详见"技术整改要点"）：
1. 物理与环境安全
2. 网络与通信安全
3. 设备与计算安全（主机安全）
4. 应用与数据安全
5. 安全建设管理
6. 安全运维管理

### 步骤六：管理整改实施

1. **完善管理制度**：编制 / 修订安全管理总纲、各专项管理制度。
2. **设立安全管理机构**：成立信息安全领导小组、信息安全工作小组。
3. **人员管理**：明确安全岗位、开展人员安全审查、签署保密协议、定期培训。
4. **建设管理**：系统建设期的方案评审、产品采购、软件开发、工程实施、测试验收。
5. **运维管理**：资产盘点、介质管理、设备维护、漏洞管理、应急预案、事件处置。

### 步骤七：等级测评（正式测评）

1. 委托**公安部认可的等级保护测评机构**开展正式测评。
2. 测评方法：访谈、文档审查、配置检查、工具测试、渗透测试。
3. 测评结论：
   - **优**：所有控制项符合
   - **良**：不存在严重不符合项
   - **中**：存在个别严重不符合项但不影响系统总体安全
   - **差**：存在多个严重不符合项，系统总体安全风险高
4. 测评得分 **70 分以上且无高危风险**为合格。
5. 出具《网络安全等级保护测评报告》，报告报送公安机关备案。

### 步骤八：取得测评报告与持续改进

1. 测评合格后，将《测评报告》提交公安机关备案。
2. **三级系统每年至少测评一次**（年度测评）。
3. 系统发生重大变更时，需重新测评。
4. 持续改进：根据测评发现的问题，逐年优化安全防护能力。

## 技术整改要点

### 一、物理与环境安全
- [ ] **物理位置**：机房选址在具有防震、防风、防水的建筑内。
- [ ] **物理访问控制**：机房入口部署门禁（双因素）、视频监控（留存 ≥ 90 天）。
- [ ] **防盗窃防破坏**：设备固定、机柜上锁、防雷接地。
- [ ] **防雷防火**：部署火灾自动消防系统、防雷器。
- [ ] **防水防潮**：机房防水、安装水浸检测。
- [ ] **防静电**：防静电地板、接地。
- [ ] **温湿度控制**：精密空调，温度 18-28℃，湿度 35%-75%。
- [ ] **电力供应**：双路市电 + UPS + 备用发电机，UPS 至少支撑 4 小时。
- [ ] **电磁防护**：电源线与信号线隔离敷设，必要时电磁屏蔽。

> 如使用云服务（阿里云、腾讯云等），云厂商通常已通过等保测评，可继承云平台物理安全结论，重点整改虚拟化层之上的内容。

### 二、网络与通信安全
- [ ] **网络架构**：划分安全域（DMZ、应用区、数据区、管理区），网段隔离。
- [ ] **通信传输**：使用 TLS 1.2+ 加密通信；DoctorAgent API 启用 HTTPS。
- [ ] **边界防护**：部署下一代防火墙（NGFW），配置访问控制策略。
- [ ] **访问控制**：网络设备、安全设备配置 ACL。
- [ ] **入侵防范**：部署 IDS/IPS，规则库定期更新。
- [ ] **恶意代码防范**：网络层防病毒网关、APT 检测。
- [ ] **安全审计**：网络设备日志集中收集，留存 ≥ 6 个月。
- [ ] **DDoS 防护**：抗 DDoS 设备或云防护服务。

### 三、设备与计算安全（主机安全）
- [ ] **身份鉴别**：操作系统、数据库多因素认证，密码复杂度要求。
- [ ] **访问控制**：最小权限原则，账户权限分离。
- [ ] **安全审计**：操作系统、数据库审计日志开启，集中收集。
- [ ] **入侵防范**：主机入侵检测（HIDS）、补丁管理。
- [ ] **恶意代码防范**：服务器部署 EDR / 防病毒软件。
- [ ] **资源控制**：CPU、内存、磁盘资源监控与告警。
- [ ] **补丁管理**：定期漏洞扫描，关键补丁 30 天内修复。
- [ ] **基线加固**：按 CIS Benchmark / 等保基线加固操作系统。

### 四、应用与数据安全
- [ ] **身份鉴别**：DoctorAgent 应用多因素认证（密码 + OTP / 生物识别）。
- [ ] **访问控制**：基于 RBAC 的细粒度权限控制（DoctorAgent 已实现 7 角色 + 临床角色）。
- [ ] **安全审计**：应用操作日志，HMAC 签名防篡改（DoctorAgent 已实现审计链）。
- [ ] **软件容错**：输入校验、防 SQL 注入、防 XSS、防 CSRF。
- [ ] **资源控制**：会话超时、并发限制、速率限制（DoctorAgent 已实现 rate_limit）。
- [ ] **数据完整性**：关键数据校验、HMAC、数字签名。
- [ ] **数据保密性**：传输加密（TLS）、存储加密（AES-256-GCM，DoctorAgent 已实现）。
- [ ] **数据备份恢复**：本地 + 异地备份，定期恢复演练。
- [ ] **剩余信息保护**：用户鉴别信息使用后立即清除。
- [ ] **个人信息保护**：PII 脱敏（DoctorAgent 已实现 18 类标识符脱敏）、最小化采集。

### 五、安全建设管理
- [ ] **定级备案**：完成等保备案。
- [ ] **安全方案设计**：系统建设前的安全方案设计评审。
- [ ] **产品采购**：采购经过安全认证的产品（如商用密码产品认证）。
- [ ] **软件开发**：安全编码规范、代码审计、漏洞扫描。
- [ ] **工程实施**：实施过程的安全控制。
- [ ] **测试验收**：上线前的安全测试、渗透测试。
- [ ] **系统交付**：交付物清单、安全配置说明。

### 六、安全运维管理
- [ ] **环境管理**：机房环境巡视、台账管理。
- [ ] **资产管理**：资产清单、资产变更管理。
- [ ] **介质管理**：存储介质使用、销毁记录。
- [ ] **设备维护**：维护审批、维护记录。
- [ ] **漏洞和风险管理**：定期漏洞扫描、风险评估。
- [ ] **网络和系统安全管理**：配置基线、变更管理。
- [ ] **恶意代码防范管理**：防病毒策略、规则更新。
- [ ] **安全事件处置**：事件分级、应急响应流程。
- [ ] **应急预案管理**：应急预案演练（每年至少 1 次）。
- [ ] **配置管理**：配置基线、变更审批。

## 办理机构

| 办理事项 | 机构 | 备注 |
|----------|------|------|
| 定级 | 主体自行定级 + 专家评审 | 专家应具有相关资质 |
| 备案 | **所在地设区的市级及以上公安机关网安部门** | 备案证明 |
| 测评 | **公安部认可的等级保护测评机构** | 第三方独立机构 |
| 整改实施 | 主体自行 / 委托安全集成商 | 可选 |
| 监督检查 | 公安机关网安部门 | 三级每年至少测评 1 次 |
| 安全产品采购 | 通过认证的安全产品厂商 | 商用密码产品需 CMVP 认证 |

### 测评机构选择
1. 选择经**公安部认可的等级保护测评机构**（"国家网络安全等级保护工作协调小组办公室"目录内）。
2. 优先选择**本省或邻近省份**的机构（便于现场测评）。
3. 优先选择具有**医疗行业测评经验**的机构。
4. 确认测评机构**具有该级别的测评资质**（部分机构仅有二级测评资质）。
5. 测评机构与被测系统应**无利益关系**（独立性要求）。
6. 测评机构目录查询：**全国等级保护测评机构推荐目录**（网安部门官网）。

## 时间周期

| 阶段 | 预计耗时 | 说明 |
|------|----------|------|
| 定级与专家评审 | 2-4 周 | 含定级报告编制 |
| 备案 | 2-3 周 | 公安机关审核 |
| 差距分析 | 2-4 周 | 测评机构现场摸底 |
| 整改方案设计 | 1-2 周 | 可与差距分析并行 |

| 管理制度编制 | 1-2 个月 | 可与技术整改并行 |

## 注意事项

1. **等保是强制义务**：未履行等保义务的，公安机关可责令改正、警告；拒不改正的处**1 万元以上 10 万元以下罚款**；造成严重后果的可追究刑事责任（《网络安全法》第五十九条）。
2. **测评 ≠ 备案**：备案是公安机关行政确认；测评是技术评估。两者均需办理，备案在前，测评随后。
3. **测评合格不等于永久合规**：三级系统**每年至少测评一次**，未按时测评同样违规。
4. **云上部署的继承性**：使用公有云部署时，云平台的物理、网络层安全可继承云厂商等保结论（如阿里云、腾讯云已通过等保三级），主体重点整改虚拟化层之上的内容（应用、数据、管理）。
5. **测评机构独立性**：测评机构不得参与被测系统的建设、整改，确保客观公正。
6. **整改要彻底**：测评报告中的不符合项需在下次测评前整改完毕，否则影响年度合规。
7. **数据安全合规叠加**：等保是基础，处理个人信息的还需符合《个人信息保护法》《数据安全法》的额外要求（如 PIA 评估、数据出境评估）。
8. **关键信息基础设施（CII）额外要求**：若 DoctorAgent 部署于被认定为 CII 的医疗机构，需按《关键信息基础设施安全保护条例》履行额外义务（如供应链安全、安全审查）。
9. **商用密码合规**：使用商用密码算法（SM2/SM3/SM4）的，相关产品需通过商用密码产品认证。
10. **应急预案演练**：每年至少开展 1 次应急演练，留存演练记录与改进措施。
11. **日志留存要求**：网络、主机、应用日志至少留存 **6 个月**（关键信息基础设施要求 12 个月）。
12. **供应链安全**：采购的软硬件产品需评估供应商安全风险，重要系统采购需开展安全审查。

## 常见问题

### Q1：DoctorAgent 部署在公有云上，还需要做等保吗？
需要。云上部署同样需要等保，但可继承云平台的物理、网络层等保结论（云厂商已通过等保三级）。主体重点整改虚拟化层之上的内容（应用、数据、管理），测评机构测评范围相应缩小。

### Q2：等保三级和等保二级差别大吗？
差别较大。等保三级比二级要求：
- 测评频率：三级每年 1 次，二级建议每两年 1 次
- 安全要求：三级增加了部分控制点（如剩余信息保护、个人信息保护、密码管理）
- 测评深度：三级测评更严格，访谈、测试更全面
- 投入：三级整改与年度运维投入约为二级的 2-3 倍

### Q3：测评不合格怎么办？
测评不合格的，需在公安机关规定时间内完成整改，重新测评。如长期不达标，公安机关可责令暂停业务、行政处罚。

### Q4：系统升级改造后需要重新测评吗？
**重大变更**（架构变化、核心功能扩展）需重新测评；**轻微变更**（小版本升级、配置调整）可在年度测评中覆盖。

### Q5：等级测评报告有效期多久？
报告本身无有效期，但三级系统每年需重新测评。每年测评报告均需报送公安机关。

### Q6：SaaS 模式下，DoctorAgent 作为 SaaS 提供商，等保由谁做？
**SaaS 提供商做等保**。DoctorAgent SaaS 平台作为一个定级对象，由 DoctorAgent 运营方完成等保。医院作为用户，可要求 SaaS 方提供等保证明，自身无需重复等保（但需评估接入合规性）。

### Q7：等保和 ISO 27001、SOC 2 是什么关系？
- **等保**：中国强制合规，公安机关监督，境内运营必须办理。
- **ISO 27001**：国际自愿性认证，体系化安全管理。
- **SOC 2**：美国审计师协会标准，主要面向 SaaS 服务可信度。
三者体系不同但相互补充。境内运营优先办理等保，海外业务另办 ISO 27001 / SOC 2。

### Q8：医生使用 DoctorAgent 是不是要给医生定级？
不对个人定级，是对信息系统定级。但需对医生账户做权限管理（RBAC）、身份认证、审计。

### Q9：等保测评会做渗透测试吗？会影响业务吗？
三级测评通常包含渗透测试，但会与被测方约定测试时间窗口，避开业务高峰，必要时采用灰盒测试，降低对业务的影响。建议提前与测评机构沟通测试范围与时间。

### Q10：多个医院部署 DoctorAgent，每个医院都要单独等保吗？
- **SaaS 模式**：DoctorAgent 中心平台一次等保即可，各医院接入无需单独等保。
- **私有化部署**：每个部署实例需独立定级备案（不同医院的系统是独立的定级对象）。建议采用 SaaS 模式降低合规成本。
