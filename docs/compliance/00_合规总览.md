# DoctorAgent 合规总览

> 本文档面向使用 DoctorAgent 的企业用户，提供全部合规资质的总览、办理优先级建议、快速自查清单，以及 DoctorAgent 合规自检工具的使用说明。
> 详细操作步骤请参阅对应的专项教程。

## 一、合规资质总览

DoctorAgent 是一个临床决策支持（CDS）+ 医疗 AI Agent 平台，涉及医疗器械、AI 算法、网络安全、数据保护、伦理审查等多维合规要求。下表汇总所有资质及其属性：

### 资质清单表

| # | 资质名称 | 是否必须 | 适用场景 | 办理周期 | 办理机构 | 教程链接 |
|---|----------|----------|----------|----------|----------|----------|
| 1 | NMPA 医疗器械注册证（二类 / 三类） | **必须**（作为医疗器械销售时） | 在中国境内作为医疗器械销售或部署 | 12-18 个月（二类）；18-24 个月（三类） | 省级药监局（二类）/ 国家药监局 CMDE（三类） | [01_NMPA医疗器械认证教程](01_NMPA医疗器械认证教程.md) |
| 2 | 生成式 AI / 深度合成算法备案 | **必须**（向公众提供 AI 服务时） | DoctorAgent 提供对话式 AI、文本生成服务 | 2-4 个月 | 国家网信办 | [02_生成式AI算法备案教程](02_生成式AI算法备案教程.md) |
| 3 | 网络安全等级保护三级（等保 2.0） | **必须**（医疗信息系统） | DoctorAgent 部署在医院核心网络、处理敏感医疗数据 | 6-9 个月 | 公安机关 + 等级测评机构 | [03_等保三级认证教程](03_等保三级认证教程.md) |
| 4 | IRB 伦理审查批件 | **必须**（涉及患者数据研究时） | 开展临床验证、临床试验、回顾性研究、模型训练验证 | 2-4 个月（会议审查） | 医院 / 区域 / 独立伦理委员会 | [04_IRB伦理审查教程](04_IRB伦理审查教程.md) |
| 5 | 数据安全合规（三法 + 医疗数据） | **必须** | 处理患者数据、个人信息、重要数据 | 6-12 个月（体系建立） | 网信办 + 行业主管部门 | [05_数据安全合规教程](05_数据安全合规教程.md) |
| 6 | HIPAA 合规 | **视情况必须**（面向美国市场时） | 处理美国公民 PHI、向美国医疗客户提供 services | 6-12 个月（合规建立）；6-12 个月（HITRUST 认证） | HHS 民权办公室（OCR）+ 第三方认证机构 | [06_HIPAA合规教程](06_HIPAA合规教程.md) |

### 资质属性说明

#### 是否必须的判断逻辑
- **NMPA 医疗器械注册**：DoctorAgent 定位为临床决策支持工具，作为医疗器械销售必须办理。如仅作为通用知识检索工具（不输出临床建议），可能豁免，但需分类界定确认。
- **算法备案**：DoctorAgent 提供对话式 AI、医学文本生成能力，属生成式 AI 服务，必须备案。即使内网部署、医院内部使用，也建议备案。
- **等保三级**：DoctorAgent 处理敏感医疗数据，建议统一按等保三级规划。即使部分场景可定二级，按三级建设能覆盖更广合规需求。
- **IRB 伦理审查**：凡涉及患者数据的研究、验证、评估活动，开展前必须取得 IRB 批件。豁免审查需 IRB 确认，不能自行决定。
- **数据安全合规**：处理患者数据即必须履行三法义务。涉及数据出境、人类遗传资源的，需额外办理相应审批。
- **HIPAA 合规**：仅面向美国市场时必须。仅服务中国市场可不做。

## 二、合规时间线建议

### 并行推进策略

DoctorAgent 的多项合规工作可并行推进，建议按以下时间线规划（T 表示启动时间）：

```
T+0 ──────────────────────────────────────────────────────► T+18 月
│
├─ 算法备案（T+0 → T+4 月）                  ◄── 并行启动
│   ├─ ICP 备案（前置）
│   ├─ 算法安全评估
│   └─ 网信办备案审核
│
├─ 等保三级（T+0 → T+6 月）                  ◄── 并行启动
│   ├─ 定级备案（T+0~1 月）
│   ├─ 差距分析（T+1~2 月）
│   ├─ 整改（T+2~4 月）
│   └─ 测评（T+4~6 月）
│
├─ 数据安全合规体系（T+0 → T+12 月）          ◄── 并行启动
│   ├─ 数据分类分级（T+0~2 月）
│   ├─ PIA 评估（T+1~3 月）
│   ├─ 数据出境评估（如需，T+1~6 月）
│   └─ 制度体系建立（T+0~6 月，持续优化）
│
├─ IRB 伦理审查（T+1 → T+3 月）              ◄── 临床验证前必须完成
│   ├─ 方案设计（T+1 月）
│   └─ 伦理审查（T+2~3 月）
│
├─ NMPA 二类医疗器械注册（T+3 → T+18 月）     ◄── 等待其他资质就绪后启动
│   ├─ 分类界定（T+3~5 月）
│   ├─ QMS 建立（T+3~6 月，可前置）
│   ├─ 注册检验（T+5~9 月）
│   ├─ 临床评价（T+6~12 月，需 IRB 批件）
│   └─ 注册审评（T+12~18 月）
│
└─ HIPAA 合规（如需，T+6 → T+12 月）         ◄── 国际市场启动时启动
    ├─ 政策建立（T+6~8 月）
    ├─ BAA 签署（T+6~9 月）
    ├─ 风险评估（T+8~10 月）
    └─ HITRUST 认证（T+10~18 月，可选）
```

### 关键依赖关系
1. **算法备案 → 产品上线**：未备案不得上线，是上线的**前置条件**。
2. **等保三级 → 医院接入**：医院接入 DoctorAgent 通常要求等保三级备案证明。
3. **IRB 批件 → 临床验证 → NMPA 临床评价**：NMPA 注册的临床评价路径依赖 IRB 批件。
4. **数据出境评估 → 调用境外 API**：未完成出境评估不得调用境外 API。
5. **HIPAA → 美国市场**：进入美国市场前必须完成 HIPAA 合规。
6. **NMPA 注册 → 医疗器械销售**：作为医疗器械销售的法律前提。

### 推荐启动顺序
1. **T+0 立即启动**：算法备案、等保三级、数据安全合规体系（三者并行，互不依赖）。
2. **T+1 月启动**：IRB 伦理审查（如计划开展临床验证）。
3. **T+3 月启动**：NMPA 医疗器械注册（其他资质基本就绪，可启动长期工作）。
4. **T+6 月启动**：HIPAA 合规（如计划进入国际市场）。

### 不同阶段的合规里程碑
- **MVP 上线（T+4 月）**：算法备案完成、等保备案完成、数据安全基础合规。
- **医院接入（T+6 月）**：等保三级测评完成、数据安全体系初步建立。
- **临床验证（T+4 月起）**：IRB 批件取得。
- **医疗器械销售（T+18 月）**：NMPA 注册证取得。
- **国际市场（T+12 月起）**：HIPAA 合规建立。

## 四、DoctorAgent 合规自检工具使用说明

DoctorAgent 内置合规自检工具（`doctoragent/clinical/compliance_report.py`），可生成 HIPAA 合规自我评估报告，帮助运营方了解当前合规状态。

### 工具功能
工具基于当前配置（`AegisConfig`）与审计日志，生成结构化合规报告，覆盖以下六大维度：

| 维度 | 说明 | 对应 HIPAA Security Rule |
|------|------|--------------------------|
| **encryption（加密）** | 存储加密算法、KDF | § 164.312(a)(2)(iv) |
| **audit_logging（审计日志）** | 审计日志完整性、HMAC 验证、条目数 | § 164.312(b) |
| **access_control（访问控制）** | RBAC、OIDC SSO、MFA | § 164.312(a)(1) |
| **phi_protection（PHI 保护）** | DLP 扫描、18 类标识符脱敏 | § 164.514 |
| **key_management（密钥管理）** | Master Key、KMS、轮换 | § 164.312(a)(2)(iv) |
| **data_residency（数据驻留）** | 本地优先、云端关闭 | 最佳实践 |

### 报告核心字段
- **各维度配置详情**：每个维度的当前配置状态。
- **compliance_gaps（合规缺口）**：列出未达标的配置项。
- **overall_status（总体状态）**：
  - `compliant`：无缺口
  - `partial`：存在软性缺口（如云端回退启用）
  - `non_compliant`：存在硬性失败（如生产环境缺关键配置、审计日志被篡改）

### 使用方式
1. **配置好 DoctorAgent 后**，运行合规自检工具生成报告。
2. **检查 compliance_gaps**，逐项整改。
3. **复查 overall_status**，目标达到 `compliant`。
4. **定期运行**（建议每月 1 次），跟踪合规状态变化。
5. **将报告作为 PIA 评估、HIPAA 风险评估、等保测评的技术证据附件**。

### 使用注意事项
> ⚠️ **重要提示**：
> 1. 自检工具生成的是**自我评估报告**，**不等于第三方认证**或监管认可。
> 2. 自检报告**不替代**等保测评、HIPAA 第三方审计、PIA 评估等正式合规程序。
> 3. 自检报告可作为合规工作的**内部证据**与**技术配置证据**，用于：
>    - 内部合规跟踪
>    - PIA 评估的技术证据
>    - HIPAA 风险评估的技术证据
>    - 等保测评的配置证据
>    - 客户审计的辅助材料
> 4. 自检工具不会创建审计日志或修改配置，可在任何环境安全运行。
> 5. 报告中的 HMAC 完整性检查可发现审计日志被篡改情况。

### 推荐使用流程
```
部署 DoctorAgent → 配置安全参数 → 运行合规自检工具
                                  ↓
                            检查 overall_status
                                  ↓
                       ┌──────────┴──────────┐
                       ▼                      ▼
                  compliant            non_compliant / partial
                       │                      │
                       ▼                      ▼
            作为内部合规证据         按 compliance_gaps 整改
                                          ↓
                                    重新运行自检
                                          ↓
                                    循环至 compliant
                                          ↓
                                定期（每月）运行跟踪
```

## 六、常见问题

### Q1：DoctorAgent 当前合规状态如何？
详见 `docs/COMPLIANCE_ROADMAP.md`。当前所有合规认证均为**路线图目标，尚未取得**。在取得相应资质前，DoctorAgent 不作为医疗器械销售或使用。算法备案、等保三级、数据安全合规体系均处于"未启动"状态。

### Q2：作为中小企业，如何降低合规成本？
1. **优先办理必须项**：算法备案、等保备案（基础合规）。
2. **自行开展评估**：算法安全评估、PIA 评估可自行开展（不强制第三方）。
3. **使用云服务继承**：等保可继承云厂商结论，降低整改投入。
4. **SaaS 模式部署**：避免每家医院单独等保。
5. **本地化知识源**：避免数据出境评估成本。
6. **阶段性推进**：先满足上线必需，再逐步办理长期资质（NMPA）。

### Q3：合规不办会有什么后果？
- **算法备案**：罚款 1-10 万元，情节严重责令停服。
- **等保**：罚款 1-10 万元，拒不改正可停业整顿。
- **数据安全**：最高营业额 5% 罚款，可吊销执照、追究刑责。
- **HIPAA**：100-50,000 美元 / 项，年度上限 150 万美元 / 项，最高 10 年监禁。
- **医疗器械**：无证销售医疗器械，没收违法所得，并处货值 5-20 倍罚款。
- **业务影响**：应用商店下架、云服务商断服、客户流失。

### Q4：合规办理需要专职人员吗？
建议设立专职合规岗位或聘请顾问。中小企业可由法务、安全负责人兼任，但需保证投入时间。建议至少 1 人专职负责合规统筹。

### Q5：合规办理完成后还需要做什么？
- **持续合规运营**：合规不是一次性工作，需持续维护。
- **定期测评 / 评估**：等保每年测评、PIA 定期更新、HIPAA 风险评估年度开展。
- **跟踪法规变化**：法规会更新，需及时调整合规措施。
- **应对监管检查**：随时准备配合监管检查。

### Q6：DoctorAgent 自检工具与正式认证有什么区别？
- **自检工具**：自我评估，覆盖技术配置，用于内部跟踪与证据收集。
- **正式认证**：第三方机构独立评估，覆盖技术 + 管理 + 流程，具有公信力。
- **关系**：自检是基础，正式认证是目标。自检通过不等于认证通过，但自检不通过的几乎无法通过认证。

### Q7：合规成本能否转嫁给客户？
可以部分转嫁。SaaS 模式下，合规成本可计入服务费。私有化部署下，可在合同中约定合规成本分担。但需注意：核心合规义务（如算法备案、等保）由 DoctorAgent 运营方承担，不能完全转嫁给客户。

### Q8：不同省份的合规要求有差异吗？
- **算法备案**：全国统一（网信办）。
- **等保**：全国统一标准，由各地公安机关办理。
- **NMPA**：二类各省办理，效率可能有差异；三类全国统一。
- **数据出境**：全国统一（网信办）。
- **地方法规**：部分省市有额外数据保护地方法规（如深圳、上海），需关注。

### Q9：合规工作可以外包吗？
- **可外包**：咨询、整改实施、测评、审计、评估报告编制。
- **不可外包**：主体责任、法律责任、决策责任。即使外包，企业仍承担合规主体责任。
- **建议**：核心政策、决策、签字由内部负责，执行性工作可外包。

### Q10：DoctorAgent 升级了，需要重新做合规吗？
视升级内容：
- **轻微变更**（Bug 修复、性能优化）：不需要重新合规，留存记录。
- **重大变更**（新增功能、算法升级、数据范围扩大）：
  - 算法备案：10 个工作日内变更备案。
  - 等保：重大变更需重新测评。
  - NMPA：重大变更需变更注册。
  - PIA：新的处理活动需重新评估。
- 建议建立变更管理流程，每次升级前评估合规影响。

| 优先级 | 资质 | 启动时机 | 理由 |
|--------|------|----------|------|
| ★★★★★ | 算法备案 | 立即 | 上线前置条件，未备案不得上线 |
| ★★★★★ | 等保备案 | 立即 | 医院接入要求，法律义务 |
| ★★★★☆ | 数据安全合规体系 | 立即 | 法律义务，违规后果严重 |
| ★★★★☆ | IRB 伦理审查 | 临床验证前 | 临床研究前置条件 |
| ★★★☆☆ | 等保测评 | 备案后 | 等保合规完成 |
| ★★★☆☆ | NMPA 医疗器械注册 | 其他就绪后 | 长期工作，医疗器械销售前提 |
| ★★☆☆☆ | 数据出境评估 | 调用境外 API 前 | 仅在数据出境时办理 |

| ★☆☆☆☆ | HITRUST / SOC 2 | 业务规模扩大后 | 提升市场竞争力，非强制 |
