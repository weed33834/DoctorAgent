# 数据安全合规教程（中国三法 + 医疗数据）

> 本教程面向使用 DoctorAgent 的企业用户，指导您依据中国"三法"（《网络安全法》《数据安全法》《个人信息保护法》）及医疗健康数据相关标准，建立数据安全合规体系，并完成 DoctorAgent 中的数据安全配置。

---

## 适用场景

DoctorAgent 在运行过程中持续处理各类敏感数据：患者身份信息、电子病历、检验报告、用药记录、医患对话、医学知识库、模型推理日志等。这些数据涉及：

- **个人信息**：患者姓名、身份证号、联系方式、就诊记录等。
- **敏感个人信息**：医疗健康信息、生物识别信息等（《个保法》第二十八条）。
- **重要数据**：超过一定规模的医疗数据可能被认定为"重要数据"（《数安法》）。
- **人类遗传资源**：涉及中国人类遗传资源（基因、基因组数据）的需符合《人类遗传资源管理条例》。

DoctorAgent 的运营企业作为**数据处理者**和**个人信息处理者**，必须履行数据安全保护义务。本教程适用于：

- 在中国境内运营 DoctorAgent 的企业。
- 处理中国境内收集的患者数据的企业。
- 将数据传输至境外（含调用境外 API）的企业。
- 为医疗机构提供数据处理服务的企业。

> ⚠️ **重要提示**：违反数据安全法律可能面临高额罚款（最高营业额 5%）、责令停业、吊销执照、刑事责任。DoctorAgent 默认配置采用本地优先、加密存储、最小化采集原则，但仍需运营方落实管理制度与流程。

## 数据分类分级方案

### 一、分类（按数据类别）

依据 YD/T 3947《健康医疗数据安全指南》与 GB/T 38667，医疗数据分为 8 大类：

| 数据类别 | 说明 | DoctorAgent 中的体现 |
|----------|------|---------------------|
| 个人属性数据 | 姓名、身份证、联系方式等 | 患者基本信息 |
| 健康状况数据 | 病史、诊断、检验、影像 | 患者主诉、检验结果、诊断 |
| 医疗应用数据 | 门诊、住院、用药、手术 | 用药记录、医嘱 |
| 医疗支付数据 | 医保、费用、结算 | 就诊费用 |
| 卫生资源数据 | 医疗机构、设备、人员 | 医院信息、医生信息 |
| 公共卫生数据 | 疾病监测、流行病学 | 群体健康数据 |
| 医学科研数据 | 临床研究、生物样本 | 模型训练数据、研究数据 |
| 医疗管理数据 | 医院管理、统计 | 系统运营数据 |

### 二、分级（按敏感度与影响）

依据 GB/T 38667《健康医疗数据分类分级指南》，分为 5 级：

| 级别 | 名称 | 判定标准 | DoctorAgent 中的数据示例 | 保护要求 |
|------|------|----------|--------------------------|----------|
| 5 级 | 极敏感 | 涉及国家安全、人类遗传资源核心数据 | 基因组数据、群体基因数据 | 最高级别保护，专网传输 |
| 4 级 | 高敏感 | 个人核心隐私、大规模群体健康数据 | 完整电子病历、HIV 等敏感诊断 | 加密存储 + 严格访问控制 + 审计 |
| 3 级 | 敏感 | 个人健康信息、可识别身份 | 患者姓名 + 诊断、用药记录 | 加密存储 + 访问控制 + 审计 |
| 2 级 | 内部 | 内部运营数据、不可识别个人 | 医生账户、科室信息 | 访问控制 + 审计 |
| 1 级 | 公开 | 已公开数据 | 公开医学知识、药品说明书 | 基本保护 |

### 三、DoctorAgent 数据分级示例

| 数据项 | 推荐级别 | 加密 | 访问控制 | 审计 | 脱敏 |
|--------|----------|------|----------|------|------|
| 患者姓名 + 诊断 | 4 级 | ✓ AES-256 | ✓ RBAC | ✓ HMAC | 用户访问时脱敏 |
| 患者检验结果 + 身份证号 | 5 级 | ✓ AES-256 | ✓ RBAC + MFA | ✓ HMAC | 不向用户展示身份证号 |
| 用药提醒记录 | 3 级 | ✓ AES-256 | ✓ RBAC | ✓ HMAC | — |
| 医生账户信息 | 2 级 | ✓ | ✓ RBAC | ✓ | — |
| 公开医学知识库 | 1 级 | 可选 | 公开访问 | — | — |
| 模型推理日志 | 3 级 | ✓ | ✓ | ✓ | 含 PHI 时脱敏 |
| 系统运营日志 | 2 级 | ✓ | ✓ | ✓ | — |

### 四、定级流程
1. 编制**数据资产清单**（DoctorAgent 处理的所有数据项）。
2. 按 YD/T 3947 进行分类。
3. 按 GB/T 38667 进行分级。
4. 编制《数据分类分级目录》，明确每项数据的级别与保护要求。
5. 数据级别发生变化时（如新增数据项、数据合并）及时更新。
6. 涉及"重要数据"的（如大规模群体健康数据），按《重要数据识别指南》识别并向主管部门报备。

## 个人信息保护影响评估（PIA）

### 何时需要做 PIA
依据《个保法》第五十五条，以下情形**事前**必须开展 PIA：
1. 处理**敏感个人信息**（DoctorAgent 处理医疗健康信息，必然触发）。
2. 利用个人信息进行**自动化决策**（DoctorAgent 提供用药建议属自动化决策）。
3. **委托处理**个人信息、向其他处理者**提供**个人信息、**公开**个人信息。
4. 向**境外提供**个人信息。
5. 其他对个人权益有重大影响的处理活动。

### PIA 评估内容（依 GB/T 39335）
1. **个人信息的处理目的、处理方式是否合法、正当、必要**。
2. 对个人权益的影响及安全风险。
3. 所采取的保护措施是否合法、有效并与风险程度相适应。

### PIA 实施步骤
1. **组建评估小组**：法务、安全、业务、IT 部门共同参与。
2. **梳理处理活动**：数据流图、处理目的、数据项、处理方式、共享情况。
3. **合法性评估**：是否取得合法依据（同意 / 履行合同 / 法定义务等）。
4. **必要性评估**：是否最小化采集、最小化使用。
5. **风险评估**：识别泄露、滥用、丢失、篡改、未授权访问等风险。
6. **保护措施评估**：加密、访问控制、审计、应急预案是否充分。
7. **出具《PIA 评估报告》**：处理活动描述、合法性分析、风险分析、保护措施、改进建议、评估结论。
8. **处理报告建议**：根据评估结果改进处理活动。
9. **评估报告与处理记录至少保存 3 年**。

### PIA 报告必备要素
- [ ] 处理活动基本信息（处理者、目的、方式、数据项）
- [ ] 数据流图
- [ ] 合法性依据分析
- [ ] 必要性分析
- [ ] 风险识别与评估
- [ ] 已采取的保护措施
- [ ] 改进建议与整改计划
- [ ] 评估结论（低 / 中 / 高风险）
- [ ] 评估人员签字与日期

## 数据出境安全评估流程

### 何时需要做数据出境评估
依据《数据出境安全评估办法》，符合以下任一情形需向网信办申报数据出境安全评估：
1. 关键信息基础设施运营者（CIIO）出境个人信息。
2. 处理 **100 万人以上**个人信息的数据处理者出境个人信息。
3. 累计出境个人信息**达 10 万人**或敏感个人信息**达 1 万人**。
4. 出境**重要数据**。
5. 网信办规定的其他情形。

### DoctorAgent 数据出境场景识别
| 场景 | 是否出境 | 评估要求 |
|------|----------|----------|
| 调用 OpenAI 等境外大模型 API（含用户查询） | **是** | 触发评估 |
| 调用 PubMed、openFDA 等境外医学知识 API（含查询） | **是** | 视查询内容触发评估 |
| 境内 SaaS，数据全部境内存储 | 否 | 无需评估 |
| 跨国集团内部将境内数据传至境外总部 | **是** | 触发评估 |
| 境外远程访问境内服务器查看数据 | **是** | 触发评估 |

> DoctorAgent 默认配置采用本地化知识源，建议**优先使用境内 API 与知识库**，避免数据出境。如必须调用境外 API，需先完成出境评估。

### 数据出境路径（三选一）
1. **数据出境安全评估**（向网信办申报，强制情形必走）
2. **个人信息保护认证**（如中国网络安全审查技术与认证中心认证）
3. **标准合同（SCC）**（与境外接收方签署标准合同并向网信办备案）

### 数据出境安全评估流程
1. **识别出境行为**：明确哪些数据传至境外、接收方、目的。
2. **判断是否触发强制评估**：核对上述触发条件。
3. **开展自评估**：
   - 出境数据合法性、正当性、必要性
   - 接收方所在国家 / 地区的法律环境
   - 接收方的数据安全保护能力
   - 出境后数据再转移风险
   - 数据安全风险与维权渠道
4. **编制《数据出境风险自评估报告》**。
5. **准备申报材料**（详见"所需材料清单"）。
6. **向网信办申报**：通过所在地省级网信办向国家网信办申报。
7. **网信办审查**（约 7 个工作日内决定是否受理，受理后 45 个工作日内出具评估结果，复杂可延长）。
8. **取得评估结果**：
   - 通过：可开展数据出境
   - 不通过：不得出境，需整改后重新申报
9. **评估结果有效期 2 年**，到期或情况变化需重新申报。

## 患者数据全生命周期管理

按 GB/T 35273 与 DSMM（GB/T 37988），数据安全覆盖 6 个生命周期阶段：

### 一、数据采集
1. **合法性依据**：明确采集的合法依据（患者同意 / 履行医疗服务合同 / 法定义务）。
2. **最小化采集**：仅采集实现功能所需的最少数据。
3. **明示告知**：在采集前通过隐私政策、知情同意书告知采集目的、范围、方式。
4. **敏感个人信息单独同意**：医疗健康信息属敏感个人信息，需取得**单独同意**。
5. **采集日志**：记录采集时间、来源、采集人。

### 二、数据存储
1. **境内存储**：DoctorAgent 默认数据存储在境内（CIIO 与 100 万用户处理者强制境内存储）。
2. **加密存储**：所有敏感数据使用 AES-256-GCM 加密（DoctorAgent 已实现）。
3. **密钥管理**：使用三层密钥体系（Master Key → KEK → DEK），定期轮换（DoctorAgent 已实现）。
4. **访问控制**：基于 RBAC 的细粒度权限（DoctorAgent 已实现 7 角色 + 临床角色）。
5. **备份**：本地 + 异地备份，备份也需加密。
6. **存储期限**：明确各类数据的存储期限，到期删除（如就诊数据保留不少于《医疗机构病历管理规定》要求的年限，门诊 15 年、住院 30 年）。

### 三、数据使用
1. **目的限制**：仅用于采集时告知的目的，不得超范围使用。
2. **访问审计**：所有数据访问记录 HMAC 签名审计日志（DoctorAgent 已实现），留存至少 6 个月。
3. **脱敏展示**：用户界面展示时对敏感字段脱敏（如身份证号显示为 110***1234）。
4. **最小权限**：员工仅能访问其职责所需的最少数据。
5. **行为监测**：异常访问行为（如批量导出、非工作时间访问）实时告警。

### 四、数据加工
1. **算法处理合规**：使用 AI 处理个人信息的，需开展 PIA 评估。
2. **自动化决策透明**：向用户提供决策说明，支持拒绝自动化决策。
3. **训练数据合规**：模型训练数据需合法来源，涉及患者数据需取得授权或脱敏。
4. **数据安全监测**：加工过程实时监测，防止数据泄露。

### 五、数据传输
1. **加密传输**：所有数据传输使用 TLS 1.2+ 加密。
2. **接口安全**：API 接口认证、限流、审计。
3. **境内传输**：境内主体间传输需签署数据处理协议。
4. **出境传输**：依"数据出境安全评估流程"办理。
5. **共享 / 委托处理**：签署数据处理协议（DPA），明确双方义务。

### 六、数据销毁
1. **销毁场景**：存储期满、用户请求删除、业务终止。
2. **销毁方式**：物理销毁（硬盘消磁、粉碎）+ 逻辑销毁（密钥销毁使密文不可恢复）。
3. **销毁记录**：记录销毁时间、方式、操作人、监督人。
4. **不可恢复性验证**：销毁后验证数据不可恢复。
5. **备份销毁**：包括所有备份介质的销毁。

## 数据安全应急预案

### 一、事件分级
依据《信息安全技术 网络安全事件应急演练指南》（GB/Z 20986）：
- **特别重大（I 级）**：泄露 100 万条以上个人信息、国家安全影响。
- **重大（II 级）**：泄露 10 万条以上敏感个人信息、重要数据泄露。
- **较大（III 级）**：泄露 1 万条以上敏感个人信息。
- **一般（IV 级）**：其他数据安全事件。

### 二、应急响应流程
1. **发现与报告**：任何员工发现事件后 1 小时内报告安全负责人。
2. **初步评估**：安全负责人 2 小时内评估事件级别。
3. **启动响应**：根据级别启动相应预案。
4. **遏制与消除**：隔离受影响系统、阻断泄露、修复漏洞。
5. **证据保全**：留存系统日志、操作日志、事件记录。
6. **影响评估**：评估受影响数据范围、用户数量。
7. **通知用户**：及时通知受影响用户（告知事件、影响、应对措施、维权渠道）。
8. **监管报告**：
   - 网络安全事件：向公安机关 / 网信办报告（重大事件 24 小时内）
   - 个人信息泄露：向网信办报告（重大事件立即报告）
9. **恢复与复盘**：恢复服务、开展事后调查、改进措施、形成事件报告。

### 三、应急预案必备要素
- [ ] 应急组织架构与职责
- [ ] 事件分级标准
- [ ] 报告与响应流程
- [ ] 各级事件处置方案
- [ ] 通知用户与监管的模板
- [ ] 数据恢复方案
- [ ] 公关与媒体应对
- [ ] 法律咨询支持
- [ ] 演练计划（每年至少 1 次）

## DoctorAgent 中的数据安全配置项说明

DoctorAgent 已内置多项数据安全能力，部署时需正确配置以发挥合规作用：

### 一、加密配置
- **存储加密**：默认启用 AES-256-GCM 字段级加密，敏感字段（患者姓名、身份证、诊断、检验结果）自动加密。
- **三层密钥体系**：Master Key → KEK → DEK，建议配置 KMS（如阿里云 KMS、华为云 KMS）托管 Master Key。
- **密钥轮换**：默认每 90 天轮换 DEK，建议根据合规要求调整轮换周期。
- **传输加密**：默认启用 TLS 1.2+，建议配置 HSTS 强制 HTTPS。

### 二、访问控制配置
- **RBAC 角色**：内置 7 角色（admin / clinician / nurse / pharmacist / researcher / auditor / viewer）+ 临床角色。按最小权限原则分配。
- **多因素认证（MFA）**：生产环境强制启用 MFA（建议使用 TOTP）。
- **OIDC SSO**：支持与医院身份系统对接（如 Keycloak、Azure AD）。
- **会话管理**：建议配置会话超时（30 分钟无操作自动登出）。

### 三、审计日志配置
- **HMAC 签名**：审计日志默认启用 HMAC 签名，防篡改。
- **审计范围**：覆盖登录、数据访问、配置变更、数据导出、权限变更。
- **日志留存**：默认 6 个月，关键信息基础设施建议 12 个月。
- **日志备份**：建议独立存储与备份，与生产系统隔离。

### 四、PHI 保护配置
- **DLP 扫描**：默认启用数据丢失防护（DLP），扫描出站内容中的 PHI。
- **18 类标识符脱敏**：默认启用 HIPAA Safe Harbor 18 类标识符脱敏。
- **脱敏规则**：可配置脱敏策略（如姓名显示首字 + *、身份证号后 4 位）。

### 五、数据驻留配置
- **本地优先**：默认本地知识源（RxNorm、ICD-10、本地药品库）。
- **云端关闭**：默认云端 API 调用关闭（避免数据出境）。
- **境外 API 控制**：如 openFDA、PubMed 默认关闭，需手动开启并完成数据出境评估后方可使用。

### 六、合规自检工具
- **合规报告生成**：运行 `compliance_report` 工具生成自评估报告（覆盖加密、审计、访问控制、PHI、密钥、驻留）。
- **使用注意**：自检报告是**自我评估**，不等于第三方认证或监管认可。

## 注意事项

1. **三法叠加适用**：《网安法》《数安法》《个保法》对同一处理活动可能同时适用，需同时合规。
2. **CIIO 严要求**：被认定为关键信息基础设施的，数据必须境内存储，出境需强制评估。
3. **100 万用户红线**：处理 100 万人以上个人信息的数据处理者，出境需强制评估，建议提前规划数据规模。
4. **重要数据识别**：医疗数据可能被认定为重要数据（如群体健康数据、基因数据），需主动识别并报备。
5. **人类遗传资源特殊管理**：涉及中国人类遗传资源（基因、基因组、器官、组织、细胞）的采集、保藏、利用、对外提供需科技部审批，违规后果严重。
6. **自动化决策透明**：DoctorAgent 提供用药建议属自动化决策，需向用户提供说明，支持用户拒绝。
7. **数据可携带权**：用户请求数据转移的，应提供可读格式。
8. **数据删除权**：用户请求删除的，应在合理时限内删除（除非法律另有规定，如病历保存义务）。
9. **儿童信息特别保护**：处理未满 14 周岁未成年人信息的，需取得监护人同意并制定专门规则。
10. **第三方处理者管理**：委托第三方处理数据的，需签署 DPA，并监督其合规情况。
11. **数据泄露通知义务**：发生或可能发生个人信息泄露的，应立即采取补救措施，并通知用户与监管部门（《个保法》第五十七条）。
12. **境外数据提供合规**：禁止向境外司法或执法机构提供存储于境内的数据，未经主管机关批准。
13. **AI 训练数据合规**：使用患者数据训练 AI 的，需符合《生成式 AI 管理暂行办法》第十一条要求，合法来源 + 标注合规。
14. **数据出境记录**：所有数据出境行为需留存记录，至少 3 年。
15. **年度合规审计**：处理大量个人信息的企业应定期开展合规审计。

## 常见问题

### Q1：DoctorAgent 调用 PubMed 查文献，算数据出境吗？
算。PubMed 是美国国家医学图书馆的服务，查询内容传至境外服务器。如查询内容不含患者 PHI，仅查询关键词，风险较低但仍是出境行为。如查询包含患者信息（如以患者症状为关键词查询），需评估并采取合规路径。

### Q2：DoctorAgent 默认配置是否已满足三法要求？
DoctorAgent 默认配置已具备技术保护能力（加密、审计、访问控制、PHI 脱敏、本地优先），但**管理制度、PIA 评估、出境评估、应急预案**等需运营方自行落实。技术 + 管理双重合规才是完整合规。

### Q3：用户请求数据删除，但法律规定病历需保存 15 年，怎么办？
按法律优先原则：法定保存义务优先于删除请求。应告知用户"依《医疗机构病历管理规定》需保存至法定年限，到期后删除"，但停止处理（不再用于业务目的）。

### Q4：DoctorAgent 用历史患者数据训练模型，需要重新取得患者同意吗？
需视原始知情同意范围：
- 原始同意包含"未来研究"用途 → 可继续使用
- 原始同意未包含 → 需重新取得同意，或申请 IRB 豁免知情同意（回顾性 + minimal risk）

### Q5：跨国公司内部数据共享，需要做数据出境评估吗？
需要。集团内部跨境数据传输同样属数据出境，需走评估 / 认证 / SCC 三路径之一。

### Q6：DoctorAgent 处理多少患者数据会被认定为"重要数据"？
重要数据识别按行业主管部门标准。医疗行业的重要数据可能包括：群体基因数据、大规模健康统计数据、关键医疗资源数据等。建议主动向卫健委咨询识别标准。

### Q7：发生数据泄露，多久内通知用户和监管？
- **立即**采取补救措施。
- **及时**通知用户（告知事件、影响、应对、维权渠道）。
- **立即**向网信办等监管部门报告重大事件。
具体时限视事件严重程度，建议重大事件 24 小时内报告监管。

### Q8：DoctorAgent 自检工具生成的合规报告可以替代 PIA 吗？
不可以。自检工具是技术配置的自我评估，PIA 是法律要求的处理活动影响评估，两者维度不同。建议将自检报告作为 PIA 的技术证据附件。

### Q9：患者出院后，数据还需要继续处理吗？
按医疗服务合同目的，出院后诊疗目的已达成。但依《病历管理规定》需保存至法定年限（门诊 15 年、住院 30 年）。保存期内停止业务处理，仅供法律要求或患者请求时使用。

### Q10：DoctorAgent 与第三方医学知识库对接，数据共享需要做什么？
需评估：
- 共享内容是否含 PHI（建议仅共享查询关键词，不含患者标识）
- 签署数据处理协议（DPA）
- 评估第三方数据安全能力
- 必要时做 PIA 评估

### Q11：使用境外开源医学模型（如基于 Llama 微调），训练数据合规吗？
需评估：
- 训练数据来源是否合法
- 是否涉及中国境内患者数据（涉及则需合规处理）
- 模型部署后是否向中国公众提供服务（如是需算法备案）
境外模型部署境内服务存在合规风险，建议使用境内备案的国产模型。

### Q12：DoctorAgent 的合规自检报告可以提交给监管吗？
可以作为企业内部合规证据，但不等于第三方认证或监管认可。监管检查时需提供完整的制度文件、评估报告、审计日志等，自检报告只是其中一项参考。
